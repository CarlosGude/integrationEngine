# Webhook transport spike for v8

Verified 2026-09-22 against Symfony tags **v6.4.0**, **v7.4.0**, and **v8.0.0**. The bundle minimum stays PHP 8.2 / Symfony 6.4.

## Findings

1. Webhook and RemoteEvent are non-experimental in these releases. The 6.4 component changelogs record the transition; 7.4 and 8.0 retain the public contracts. Sources: [Webhook changelog](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Component/Webhook/CHANGELOG.md), [RemoteEvent changelog](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Component/RemoteEvent/CHANGELOG.md).
2. In 6.4, `parse(Request, string): ?RemoteEvent`, protected `doParse(Request, string): ?RemoteEvent`, and protected `getRequestMatcher(): RequestMatcherInterface`. In 7.4/8.0, parse/doParse additionally allow arrays. `createSuccessfulResponse(): Response` returns 202 and `createRejectedResponse(string): Response` returns 406. 7.4 accepts an optional Request through the forward-compatible implementation; 8.0 declares it explicitly. A parser returning `?RemoteEvent` works on all three. Sources: [6.4 parser](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Component/Webhook/Client/AbstractRequestParser.php), [7.4 parser](https://github.com/symfony/symfony/blob/v7.4.0/src/Symfony/Component/Webhook/Client/AbstractRequestParser.php), [8.0 parser](https://github.com/symfony/symfony/blob/v8.0.0/src/Symfony/Component/Webhook/Client/AbstractRequestParser.php).
3. **A null result is rejected with 406, not acknowledged.** Controllers do not catch `RejectWebhookException`; HttpKernel renders its HTTP status, normally 406. In 6.4 the controller does not pass Request to response factories, so a request-local marker cannot portably override ignored responses. Sources: [6.4 controller](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Component/Webhook/Controller/WebhookController.php), [7.4 controller](https://github.com/symfony/symfony/blob/v7.4.0/src/Symfony/Component/Webhook/Controller/WebhookController.php), [8.0 controller](https://github.com/symfony/symfony/blob/v8.0.0/src/Symfony/Component/Webhook/Controller/WebhookController.php).
4. Symfony routing declares `framework.webhook.routing.<type>.service` and `.secret`. Import `@FrameworkBundle/Resources/config/routing/webhook.xml` on 6.4/7.4, `@FrameworkBundle/Resources/config/routing/webhook.php` on 8.0. Sources: [6.4 route](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Bundle/FrameworkBundle/Resources/config/routing/webhook.xml), [8.0 route](https://github.com/symfony/symfony/blob/v8.0.0/src/Symfony/Bundle/FrameworkBundle/Resources/config/routing/webhook.php), [7.4 configuration guide](https://symfony.com/doc/7.4/webhook.html).
5. Every accepted event is dispatched as `ConsumeRemoteEventMessage` to a required `MessageBusInterface`. Messenger is required for the supplied controller, even for synchronous consumption. Queued execution additionally requires application routing/transports. The parser itself can be called without Messenger. See the controller sources above.
6. RemoteEvent is extensible and its constructor requires an array payload in every version. `MappedRemoteEvent` can therefore retain the decoded payload plus a typed DTO. Sources: [6.4 event](https://github.com/symfony/symfony/blob/v6.4.0/src/Symfony/Component/RemoteEvent/RemoteEvent.php), [7.4 event](https://github.com/symfony/symfony/blob/v7.4.0/src/Symfony/Component/RemoteEvent/RemoteEvent.php), [8.0 event](https://github.com/symfony/symfony/blob/v8.0.0/src/Symfony/Component/RemoteEvent/RemoteEvent.php).
7. Read raw bytes with `Request::getContent()` before JSON decoding. Check method and media type without decoding content, verify HMAC, then decode and map. Stripe explicitly requires the unmodified body: [signature verification](https://docs.stripe.com/webhooks/signature).

## Adjustment requiring a decision

The original plan's accepted-without-event assumption conflicts with all three controllers. A small explicit bundle controller can acknowledge a verified unknown event with 202 and dispatch known events through the application MessageBus. This keeps Symfony 6.4 support and avoids mutable parser state. Standard Symfony routing can alternatively be used with the reject policy. This choice must be accepted before implementing that transport behavior.

The bundle exposes event IDs and does not deduplicate. A durable application transaction owns the receipt record and side effects.
